The pre-run checklist

Print this page. Go through it the evening before, while you are awake and thinking clearly. If you cannot tick a line, you are not ready to leave.

The job Rule 1: resumable phases

  • The job is split into phases, and each phase saves its progress somewhere the next run can find it.
  • Running a phase again is safe: it skips what is already done instead of doing it twice.
  • Anything that fails goes onto a retry list, not into the void.
  • I have run the whole thing once, on a small input, while awake.

The numbers Rule 2: the provider's number

  • For every phase I know which system holds the real count, and the wrapper reads that number, not the agent's summary.
  • I have written down what "done" means as a number, before the run, so the morning is a comparison and not an opinion.

The receipt Rule 3

  • The report is written in the block that always runs (a finally block, or your language's equivalent), so an error still produces one.
  • Its first line is one word: COMPLETE, PARTIAL, HALTED or CRASHED.
  • It lists what was skipped, with the exact command to fix each gap.
  • It records what the night cost.
  • I know its limit: a power cut or a killed process means no receipt, and silence is the only clue.

While it runs Rule 4: silence is not success

  • The wrapper, not the agent, sends a heartbeat on a schedule I have written down, to somewhere I can see from my phone.
  • I know what a missing heartbeat means: the run has stopped, not finished.

The limits Rule 5: decide before you leave

  • Two spend caps: one in my script, and one at the provider's account.
  • The write boundary is a mechanism, not a sentence in the prompt. I have tested it refusing a write outside, allowing a write inside, and not blocking the tool's own folders.
  • The permission mode is the one I chose, not whatever the install defaulted to.
  • There is a written stop condition: when the run must stop instead of trying again.
  • The instructions tell the agent what a refusal means: note it, skip the item, move on, and never look for another way round.
  • The computer is set not to sleep or restart overnight.

The morning five minutes

Read the receipt in this order: the status word, the provider's number, the gaps, the money.

  • COMPLETE: check the number against what you expected anyway. Ten seconds.
  • PARTIAL: run the fix-it commands one at a time, today, and watch the first one.
  • HALTED: find out why the cap was reached before you raise it.
  • CRASHED: read the error on the first line, then the log. Do not re-run first.

If you don't understand what happened, don't re-run.

From It Ran While I Slept: How to Run AI Agents Unattended, Safely by Ethan Voss. The book explains each rule with a real overnight run: every store in one link.
